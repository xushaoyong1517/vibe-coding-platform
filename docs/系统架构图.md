## 二、核心数据流：一次报价的请求链路

```mermaid
sequenceDiagram
    autonumber
    participant U as 业务员浏览器
    participant F as 前端 SPA
    participant A as API 路由
    participant K as Kimi(AI)
    participant L as 规则引擎 lib
    participant DB as Supabase

    U->>F: 粘贴客户询价
    F->>A: POST /api/claude (param-extract)
    A->>K: 调用 Kimi 提取参数
    K-->>A: JSON 参数
    A-->>F: 结构化 items
    F->>A: POST /api/params/enrich
    A->>DB: 查词典 + 产品库
    A->>L: 归一 + 匹配
    L-->>A: 核心码/匹配结果
    A-->>F: 推断字段 + 历史命中
    Note over F,L: 确认页：deriveBOM 前移 + 高温/标准规则补齐
    F->>A: POST /api/bom/derive (主体+件号+DN)
    A->>DB: 取牌1/牌2 规则
    A->>L: deriveBOM 确定性合成
    L-->>A: BOM 15 行
    A-->>F: BOM
    F->>A: POST /api/quotes (保存)
    A->>DB: 写 quotes + quote_items 投影
```

## 四、技术栈要点

| 层 | 技术 |
|---|---|
| 前端 | Next.js 16 (App Router, Turbopack) · React 19 · Zustand · SWR · Tailwind v4 |
| API | Next.js Route Handlers（同仓 BFF，服务端直连 DB） |
| 鉴权 | 签名 Cookie 会话（Node crypto，零依赖）· 多租户按 tenant_id 隔离 |
| AI | Moonshot Kimi（`moonshot-v1-32k` / vision），prompt 在 `app/api/claude/skills/*.md` |
| 规则引擎 | `lib/*` 纯函数：deriveBOM(牌1/牌2)、high-temp、normalize、match —— 可单测、零幻觉 |
| 数据 | Supabase（PostgreSQL + Storage） |
| 集成 | 黑湖小工单 OpenAPI（销售/物料/库存增量同步）+ 浏览器扩展 |

> 设计要点：**AI 只做"模糊提取"，确定性规则做"补齐与校验"**——把易错的材质/BOM 推导从 LLM 挪到纯函数，准确率与可维护性都更高。
